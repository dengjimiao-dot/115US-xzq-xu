# R7 非团本功能重新迁移

上游已回退整份 R5/R7 导入。本次以当前上游 main 为基线，仅迁移 R7 非团本能力，保留上游团本实现；不通过合并旧分支重新引入已回退的整份文件。提交基线和 DLL 源绑定记录在 `client-patchs/r7-nonraid-update/paired-manifest.json`。

迁移覆盖 GM/GUI、普通副本精锐与假人、背包与仓库、物品改造/外观/武器装扮、任务与非团本活动、社交排行，以及对应存储和协议消费者。最新上游的背包整理、稀有装扮属性、AradPass、签到和 HoneyTime 接入保留；活动 313 使用上游 `list/event.lst` 索引解析、状态帧与领取路径，不替换为旧 R7 的同名 codec。

团本、军团及特殊隔离频道不启用普通副本精锐/假人组队投影。普通副本加载流程保留上游无缝重试的 ACK 条件和原队伍，团本继续使用原 99 字节单人队伍投影。对应边界回归包含军团包序不变、普通副本首次加载与重试、NPC 与假人互斥、背包及 SQLite 事务。

牵连检查覆盖 catalog 装配、profile 白名单、开关从 Go 到 GUI/客户端的传递、数据库适配和 sqlc 生成代码、插件宿主 ABI/加载路径/依赖顺序、构建脚本和源码引用。启动配置仍保留上游 PVF 指纹与团本策略，仅补非团本域和已有服主策略。已有内容规则解析与尚未收敛的兼容布局沿用源代码记录，本次不把旧 R7 的实机记录或手工规则表当作新组合验收。

客户端必须与对应 DLL 一起评审和更新。9 个配套 DLL 直接进入同一提交，明确依据业主要求“把dll作为配套更新文件一起提交”；每个小于 5 MB，不提交生成 exe、完整资源、日志、缓存或玩家存档。安装、配置补齐与回退步骤见 `client-patchs/r7-nonraid-update/README.md`（从仓库根解析）。

验证包括 Go 全量 build/vet/test、SQLite 集成、GUI 30 项自测、原生插件构建与机制测试、两种 modkit 安装/卸载逐字节恢复。实际数量与结果以 MR 验证段为准。未无人值守运行游戏；合并后的选角、进城、普通副本、团本、精锐/假人、领取和重登存档仍需用户手动验收，MR 保持 Draft。
